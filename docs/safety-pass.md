**Result:** all ten items had a confirmed gap at `f831d5a`. That does **not** mean all ten protections were absent. ## Rollout and limits of the evidence

1. **Before operator rollout:** configure an independent `PLATFORM_OPERATOR_TOKEN`, a monitored `PLATFORM_OPERATOR_EMAIL` (billing operator email is the fallback), and a delivering production mail adapter. Basic clients must migrate. Enrol `PLATFORM_OPERATOR_TOTP_SECRET` if using an authenticator. A provider accepting an alert or receipt does not prove inbox delivery; test delivery, attachments, bounces and provider idempotency with a controlled mailbox.
2. **Before worker rollout:** snapshot the single platform writer and tenant volumes with their matching secret versions. Restart billing-aware workers with the updated code and check ffmpeg on the worker host. A paused worker cannot send ordinary replies. An offline/unlinked worker or closed Cloud window can prevent a WhatsApp notice; the current dashboard banner does not depend on that send. Transport acknowledgement is not proof the owner read a message. A crash between reserving a WhatsApp notice and sending it can miss that notice.
3. **With a real test number:** verify WhatsApp delivery at expiry/pause, actual Meta window transitions, Baileys media downloads/reconnects, voice-note versus attachment presentation and handset playback. No real phone was connected for this pass.
4. **With each real provider account:** verify current model IDs, permissions, modality, inference, quota, latency and voice quality. A complete catalog is evidence about names only, and fake responses are not evidence about real-provider accuracy. Real backup custody, authenticator enrolment and disaster recovery must be rehearsed on the deployment. No secrets were rotated or live data modified here.
